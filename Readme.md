# Описание проекта

## Реализация

1. Добавлена папка `backend`
2. Изменён код frontend приложения для того, чтобы работал PKCE
3. Изменён конфиг для keycloak на переход на PKCE

## Запуск

Необходимо запускать docker compose с frontend приложением и keycloak, а так же отдельно запускать без docker java приложение. Проблема запуска всего в докере состоит в том, что нужен был бубен и бутылка, чтобы подружить между собой localhost для редиректа в keycloak и `http://keycloak:8080` урл для spring приложения. Было несовпадение `iss` параметра в jwt токене из-за чего всё не работало. Т.к. много времени потратил на поиск проблемы, решил уже не делать полноценную дружбу докера и spring приложения, поэтому
1. Запуск `docker compose up -d --build`
2. Запуск `backend_app.jar` из папки backend командой `java -jar backend_app.jar`

## Backend

Создан контроллер и проверка ролей пользователя на соответствие. Пользователь с ролью `prothetic_user` может выполнить запрос на бэкенд, пользователь без данной роли такой возможности не имеет

## Проверка

При переходе со страницы login на страницу ввода логина/пароля, можно увидеть следующее:
- client_id: reports-frontend
- redirect_uri: http://localhost:3000/
- state: 20a9cf14-a3eb-484d-a464-ed94f1e633e3
- response_mode: fragment
- response_type: code
- scope: openid
- nonce: 94e59f27-6fe4-4c62-8f18-dc566a2304fa
- code_challenge: zvsnp5B8qdVSmw57IuNtZmPocMBrE9_dP3bG5BFvGd4
- code_challenge_method: S256

Присутствует `code_challenge` и метод шифрования

Столкнулся с тем, что после того, как пользователь прожимает кнопку входа, идёт некоторое зацикливание на keycloak с логами connection refuse. Не разбирался, почему так происходит, но не влияет на работоспособность в итоге
