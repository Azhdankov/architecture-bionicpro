# Система проверки ролей для API

## Описание

Реализована система проверки ролей пользователей для API эндпоинтов с использованием аннотаций. Система позволяет легко добавлять проверку ролей к любым методам контроллеров.

## Компоненты

### 1. Аннотация `@RequireRole`
```java
@RequireRole("role_name")
```
- Применяется к методам контроллеров
- Указывает требуемую роль для доступа к эндпоинту

### 2. Аспект `RoleCheckAspect`
- Автоматически проверяет наличие требуемой роли у пользователя
- Выполняется перед вызовом метода с аннотацией `@RequireRole`
- Выбрасывает `SecurityException` при отсутствии роли

### 3. Глобальный обработчик исключений `GlobalExceptionHandler`
- Обрабатывает `SecurityException` и возвращает HTTP 403 Forbidden
- Предоставляет понятные сообщения об ошибках

## Использование

### Добавление проверки роли к эндпоинту

```java
@RestController
public class MyController {

    @GetMapping("/my-endpoint")
    @RequireRole("prothetic_user")
    public ResponseEntity<String> myMethod() {
        return ResponseEntity.ok("Доступ разрешен");
    }
}
```

### Примеры эндпоинтов

1. `/reports` - требует роль `prothetic_user`
2. `/reports2` - требует роль `admin_user`
3. `/reports3` - требует роль `viewer_user`

## Как это работает

1. Пользователь отправляет запрос с JWT токеном
2. `KeycloakJwtAuthenticationConverter` извлекает роли из токена
3. `RoleCheckAspect` проверяет наличие требуемой роли
4. Если роль есть - метод выполняется, если нет - возвращается 403

## Добавление новых ролей

1. Создайте роль в Keycloak
2. Назначьте роль пользователям
3. Добавьте аннотацию `@RequireRole("role_name")` к нужному методу

## Безопасность

- Роли извлекаются из JWT токена
- Проверка выполняется на уровне приложения
- Все ошибки безопасности логируются
- Возвращаются правильные HTTP статусы
